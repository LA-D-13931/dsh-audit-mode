# 审核报告模板（审核模式 · 监督 agent 用）

> **受众**：① 负责修的 agent（要可执行、可复现、最小上下文）② 拍板/签字的用户（要结论、风险、成本、需人看项）。
> **不是教学材料**：不解释基础概念、不给练习题；需要教学请另开学习模式。
> 用法：复制本文件 → `备审报告_YYYYMMDD_<主题>.md`；机器可读 findings 见 §2 的 `findings.json`。
> 规矩：**开头先说数字；没有要修的就明说；"没查什么"必填；每条 finding 必须能被回应、能被转交。**

## 2. Findings（审计版：证据 / 复核 / 回应）

机器可读源：`findings.json`（结构见 [findings.example.json](findings.example.json)）。
转交件由它生成：`node tools/生成转交.mjs --findings findings.json --out <要求/转交提示词.md>`。

| id | 严重度 | 标签 | 位置 file:line | 现象（一句话） | 证据（命令 + 原始输出 / 截图） | 复核（谁/怎么核） | 回应 | 状态 |
|---|---|---|---|---|---|---|---|---|
| F-001 | Major | Introduced | `path:12` |  |  | 第二上下文已复核 | fixed ／ wrong ／ intentional ／ ignored | 关闭 / 未关 |

规则：
- **只发布复核过的 finding**；Blocker/Major 必须由第二上下文（subagent/第二复核员）核过。
- 标签：`Introduced`（本次引入）／`Pre-existing`（历史遗留，**不算作者这次引入**）／`Nit`（风格，默认丢，不占预算）。
- 同类问题**只报一次**，同时给"全库同类扫描"的结果。
- 每条必须被回应：`fixed`（修了，附验证命令）／`wrong`（审核方判错，撤回并留痕）／`intentional`（对方有理由，记账）／`ignored`（未回应，保持打开）。
- **写给修的人的字段**（修法方向 / 验证命令 / 禁止事项）放在 §3，不在本表堆长文。

## 3. 转交件（给修的人 · agent-to-agent）

- 生成命令：`node tools/生成转交.mjs --findings findings.json --out <本工作区要求目录>/00_给开发agent的转述提示词_<轮次>.md`
- 格式见 [转交模板.md](转交模板.md)。每条包含：`file:line`、现象、复现命令、期望 vs 实际、**修法方向（不给补丁）**、**验证命令**、禁止事项。
- 本报告只放转交件指针，不重复长文。
