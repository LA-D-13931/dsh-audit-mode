# 转交模板（审核方 → 修的人 / 开发 agent）

> 这是**给 agent 的交接件**，不是给人看的教学材料。
> 由 `findings.json` 生成：`node tools/生成转交.mjs --findings findings.json --out <目标.md>`。
> 读者：负责修的 agent。要求：可执行、可复现、最小上下文、边界清楚。

---

# 给开发 agent 的转交提示词（审核模式生成）

## 0. 取样（修之前先核）

- 轮次 / 要求版本：
- 冻结 HEAD：
- 工作树：干净 / n 处
- 本轮审核报告：<路径>
- 转交时间：

## 1. 本轮要修（按严重度排序）

### F-001 · [Blocker] · Introduced · `path/to/file:12`

- **现象**：（一句话说清违反了什么）
- **证据**：`命令` ⇒ 实际输出 / 退出码（可复现）
- **期望**：（应该是什么，指到权威写法/判据/正文）
- **修法方向**：（最小改动方向；不给整段补丁）
- **验证命令**：`命令`（必须能自己跑出绿/红）
- **禁止**：不要改判据/期望/阈值；不要缩小执行面；不要动本轮范围外的文件

## 2. 本轮不要动

- 范围外文件 / 冻结的判据 / 已通过项：
- 已知假红（不是缺陷，别修）：

## 3. 交付要求（不满足就不算完成）

- 每条 finding 逐条回答：fixed / intentional / 不同意（给复现命令）
- 证据：命令 + 原始输出 + 退出码；**不许只写"已通过"**
- 冻结 commit + 工作树干净
- 回复带轮次戳；回复落后于要求是信号，不是噪声
- 若有新发现的需求/缺口：写进需求登记，不要静默绕过

## 4. 未关闭 / 不计入本轮

- Pre-existing（历史遗留，单独立项，不算本轮引入）：
- ignored（上轮未回应）：
- 没验成（2）：
